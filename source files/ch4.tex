\chapter{The Classics}
\section{QuickSort}

In general, to sort an input array of size n deterministically using only pairwise comparisons,
it can be proved via a decision tree that we need at least $\approx n\log_2 n$ operations. From a 
time complexity point of view this is $\Theta(n\log n)$ time. The STL library of \texttt{C++} uses 
\texttt{QuickSort} in its \texttt{std::sort()} function not because it does better than this 
but because it is parallelisable at the processor level (the details of which we omit since it is not 
the focus of this book!)\\

\subsection{The Algorithm}
\begin{center}
\begin{minipage}{0.9\linewidth}
\begin{framed}
\begin{Verbatim}
QuickSort(A)
{
    choose an element p from A as the "pivot"
    partition A into A<p, A=p, A>p
    return {QuickSort(A<p) : (A=p) : QuickSort(A>p)}
}
\end{Verbatim}
\vspace{-4mm}
\end{framed}
\end{minipage}
\end{center}

\noindent Note that \texttt{A<p} is our notation for the elements of \texttt{A} that are strictly less than \texttt{p}.
Similarly we can define \texttt{A>p} and \texttt{A=p} and the final result is the concatenation of the sorted 
versions of these three sets. 
For simplicity of analysis, we will assume all elements in the array are distinct since that 
is the toughest case. So \texttt{A=p} is a single element.\\


\subsection{Worst Case}
\noindent A deterministic implementation may always choose the first or last element as pivot. 
Unfortunately, this can lead to very poor performance on adversarial inputs. 
For example, if the array is already sorted and we always choose the leftmost element as 
pivot, the recursion becomes extremely unbalanced, leading to a runtime of $\Theta(n^2)$.

\[
T(n)=
(n-1)+(n-2)+\dots+1
=
\Theta(n^2)
\]

\noindent Thus \texttt{QuickSort} has worst case complexity of $\Theta(n^2)$. The standard randomised 
version instead chooses the pivot uniformly at random. This modification dramatically changes 
the behaviour of the algorithm -- it becomes very unlikely that we 
repeatedly choose extremely bad pivots.

\subsection{Expected Time Complexity}

\subsubsection*{Recurrence Relation}
Let \(T(n)\) be the random variable denoting the runtime of randomised \texttt{QuickSort} on 
an array of size \(n\).\\


\noindent Suppose the pivot is at index \(k\) (0-indexed), where \(0\le k\le n-1\). 
Then the recursive subproblems have sizes \(k\) and \(n-1-k\). Since partitioning itself 
takes n operations, we obtain a recurrence relation for \(T(n)\). 

\[
T(n)\mid \text{pivot} = k
=
T(k)+T(n-1-k)+n
\]

\noindent Because the pivot is chosen uniformly at random, every value of \(k\) is equally likely. Taking expectation 
over all random choices made by the algorithm gives
\[
\mathbb E[T(n \mid \text{pivot} = k)]
=
n
+
\frac{1}{n}\sum_{k=0}^{n-1}
\left(
T(k)+T(n-1-k)
\right)
\]

Taking expectation over all possible values of \(k\) and using the law\footnote{See \autoref{total_expectation}} of total 
expectation gives us a recurrence relation for $\mathbb E[T(n)]$ which we denote as $Y(n)$.

\[
\mathbb E[\mathbb E[T(n \mid \text{pivot} = k)]] = 
\mathbb E[T(n)]=n+\frac{1}{n}\sum_{k=0}^{n-1}\mathbb E[T(k)] + \mathbb E[T(n-1-k)]
\]

\[
\implies 
Y(n)
=
n+\frac{1}{n}\sum_{k=0}^{n-1}Y(k)+Y(n-1-k)
=
n+\frac{2}{n}\sum_{k=0}^{n-1}Y(k)
\]

\noindent Changing the variable from $Y(n)$ to $S(n)=\sum_{k=0}^{n}Y(k)$ gives us a recurrence solvable by the 
method of telescoping summation.
\[
\implies
S(n)-S(n-1)
=
n+\frac{2}{n}S(n-1)
\]

\[
\implies
S(n)
=
\left(1+\frac{2}{n}\right)S(n-1)+n
\]

\[
\implies
\frac{S(n)}{(n+1)(n+2)}
=
\frac{S(n-1)}{n(n+1)}
+
\frac{n}{(n+1)(n+2)}
\]

\[
\implies
\frac{S(n)}{(n+1)(n+2)}
-
\frac{S(n-1)}{n(n+1)}
=
\frac{2}{n+2}-\frac{1}{n+1}
\]

\vspace{0.5em}
Summing this recurrence from $1$ to $n$ gives the final result as we desired.

\[
\frac{S(n)}{(n+1)(n+2)}
=
\Theta(\log n)
\implies
S(n)=\Theta(n^2\log n)
\]

\[
\implies
Y(n)
=
S(n)-S(n-1)
=
\Theta(n\log n)
\]

Hence the expected runtime of randomised \texttt{QuickSort} is $\Theta(n\log n)$

\subsubsection*{Indicator Variables}

\noindent Here we explore an alternative method to arrive at the expected runtime of \texttt{QuickSort}. 
Observe that any pair of elements is compared at most once during the entire execution of \texttt{QuickSort}.
Without loss of generality assume the array is a permutation of $\{1,2,\dots,n\}$.
\noindent Consider the indicator variable $I_{ij}$ indicating whether elements $i$ and $j$ are compared or not.

\[
I_{ij}=
\begin{cases}
1,&\text{if elements }i,j\text{ are compared}\\
0,&\text{otherwise}
\end{cases}
\]

\vspace{0.5em}
\noindent Then the total number of comparisons $C$ is given by the sum of all $I_{ij}$.

\[
C=\sum_{1\le i<j\le n}I_{ij}
\]

Two elements are compared only if one of them becomes the first pivot chosen 
among all elements lying between them in sorted order. Since all of them are equally likely, 
we have a 2 out of \(j-i+1\) chance of this happening.

\[
\Pr(I_{ij}=1)=\frac{2}{j-i+1}
\implies
\mathbb{E}[C]
=
\mathbb{E}[\sum_{1\le i<j\le n}I_{ij}]
=
\sum_{1\le i<j\le n}\frac{2}{j-i+1}
=
\Theta(n\log n)
\]

\section{QuickSelect}

\texttt{QuickSort} is used to find the \(k\)-th smallest element\footnote{This is commonly 
referred to as the \(k\)-th order statistic of the array.} of an unsorted input array. An obvious method is 
to sort the array using \texttt{MergeSort}\footnote{\texttt{MergeSort} is a divide and conquer 
deterministic sort algorithm which runs in $\Theta(n\log n)$ time.} or \texttt{QuickSort} and then 
access the \(k\)-th element in $\Theta(1)$. But since we only care about one element, it 
seems inefficient to sort the entire array.\\

\subsection{The Algorithm}

We pick a pivot \(p\) and partition the array as before.
Basis the size of the partitions we can figure out which partition the \(k\)-th element is in.
If it is in the \texttt{A=p} partition, then we already have our answer!
Else we recurse into that partition and continue this process until we find the \(k\)-th element.

\begin{center}
\begin{minipage}{0.9\linewidth}
\begin{framed}
\begin{Verbatim}
QuickSelect(A,k)
{
    choose an element p from A as the "pivot"
    partition A into A<p, A=p, A>p
    if size(A<p) >= k                   f// k-th element is in A<p
        return QuickSelect(A<p,k)
    else if size(A<p)+size(A=p) >= k    // k-th element is in A=p
        return p
    else                                // k-th element is in A>p
        return QuickSelect(A>p,k-size(A<p)-size(A=p))
}
\end{Verbatim}
\vspace{-4mm}
\end{framed}
\end{minipage}
\end{center}

Intuitively, this is similar to \texttt{QuickSort}. However, unlike \texttt{QuickSort}, 
we recurse into only one side -- each step discarding a significant fraction of the array. This is a 
similar approach to Binary Search although not quite same since this does not assume a sorted array. 

\subsection{Expected Time Complexity}

Let \(X_i\) denote the size of the search space after \(i\) recursive calls of 
\texttt{QuickSelect}. $(X_0=n)$\\

\noindent At each step, a pivot is chosen uniformly at random and the array is partitioned around it.
Depending on the rank we are searching for, \texttt{QuickSelect} recurses into exactly one of the two partitions. 
To obtain a worst-case bound, we imagine that the algorithm always recurses into the larger partition and that 
all elements are distinct.\\


\noindent If the current search space has size \(x\), and the pivot ends up at position \(k\), 
then the larger partition has size equal to the maximum of $k-1$ and \(x-k\).\\

\noindent Averaging over all pivot positions,
\[
\mathbb E[X_{i+1}\mid X_i=x]
=
\frac1x
\sum_{k=1}^{x}
\max(k-1,x-k)
\le
\frac34(x-1)
\le
\frac34x
\]

\[
\implies
\mathbb E[X_{i+1}\mid X_i]
\le
\frac34 X_i
\]

Taking expectations and applying the law of total expectation 
(along with the fact that $X_0=\mathbb E[X_0]=n$) we get an upper bound for $\mathbb E[X_{i}]$.

\[
\mathbb E[X_{i+1}]
=
\mathbb E\!\left[\mathbb E[X_{i+1}\mid X_i]\right]
\le
\frac34\mathbb E[X_i]
\]

\[
\implies \frac{\mathbb E[X_{i+1}]}{\mathbb E[X_i]} \le \frac34
\implies
\frac{\mathbb E[X_i]}{\mathbb E[X_0]}
\le
\left(\frac34\right)^i
\implies \mathbb E[X_i] \le n \left(\frac{3}{4}\right)^i 
\]


\noindent Let $T$ be the random variable which denotes the number of recursive calls of \texttt{QuickSelect}. 
It is the first $i$ such that $X_i \le 1$. \\


\noindent Taking one comparison with the pivot as an operation of unit time, we get an upper bound on the 
expected time of \texttt{QuickSelect}.

\[
E[T_{run}] \le \sum_{i=1}^T n \left(\frac{3}{4}\right)^i \le \sum_{i=1}^{\infty} n\left(\frac{3}{4}\right)^i = 3n
\]

\noindent It is quite obvious that $E[T_{run}] \ge n$ since reading the input takes $\Theta(n)$ time. 
So the expected time complexity of \texttt{QuickSelect} is equal to \(\Theta(n)\), which is a 
significant improvement over the sort-and-access method which takes \(\Theta(n\log n)\)

\subsection{Expected Recursion Depth}

Define $H$ is the first $i$ such that $X_i \le 1$. This variable $H$ is by definition the depth of the 
recursion tree of \texttt{QuickSelect}. Why does this matter? The analysis of this quantity will illustrate 
general methods which will be useful in later chapters.\\


\noindent Since $X_i \le 1$ is equivalent to $H \le i$, $H>i$ is 
equivalent to $X_i \ge 2$. Using Markov's Inequality\footnote{See \autoref{markov_inequality}},
\[
\Pr(H>i)
=
\Pr(X_i\ge2)
\le
\frac{\mathbb E[X_i]}{2} \le \frac n2\left(\frac34\right)^i
\]

We can also use the trivial upper bound $1$ on $\Pr(H>i)$.

\[
\Pr(H>i) \le \min\left(1,\frac n2\left(\frac34\right)^i\right)
\]

\noindent Using the tail sum formula\footnote{See \autoref{tail_sum}} we can bound the expected value of $H$.

\[
\mathbb E[H]
=
\sum_{i=0}^{\infty}\Pr(H>i)
\le
\sum_{i=0}^{\infty}
\min\left(1,\frac n2\left(\frac34\right)^i\right) 
\]

\vspace{0.6em}
\subsubsection*{The Splitting Technique}
We split the sum into two parts, and bound them or find 
them separately, thus finding our overall bound. Here we split according to when 
the min() changes from $1$ to $\frac n2\left(\frac34\right)^i$.\\
\[
\mathbb E[H] \le \sum_{i=0}^{m-1} 1 +
\sum_{i=m}^{\infty} \frac{n}{2} \left( \frac{3}{4} \right)^i
=m+ \sum_{i=m}^{\infty} \frac{n}{2} \left( \frac{3}{4} \right)^i
\;\;\left(\text{where } m= \left\lceil \log_{\frac{4}{3}} \left( \frac{n}{2} \right) \right\rceil\right)
\]

\vspace{1em}
\noindent For the summation we can factor out the first term, which by our choice of $m$ is less 
than or equal to $1$. The summation left is a geometric series which evaluates to $4$.

\[
\sum_{i=m}^{\infty} \frac{n}{2} \left( \frac{3}{4} \right)^i
=
\left( \frac n2\left(\frac34\right)^m \right) \cdot 
\left(\sum_{j=m}^{\infty}\left(\frac34\right)^{j-m}\right)
\le (1) \cdot (4)
\]

\[
\implies
\mathbb E[H]
\le
m+4
=
\left\lceil
\log_{4/3}\!\left(\frac n2\right)
\right\rceil
+4
\implies
\mathbb E[H] \le \Theta(\log n)
\]

\subsection{Geometric Decline Theorem}
For a general series of random variables $X_0=n, X_1, X_2, \ldots$ and $T$ being the first 
$i$ such that $X_i \le 1$, given $\frac{\mathbb E[X_{i+1}]}{\mathbb E[X_{i}]} \le p$ 
with $0<p<1$, the expected value of $T$ is at most $\Theta(\log n)$. The proof of this theorem is merely a 
generalisation of the proof for the recursion depth of \texttt{QuickSelect} and is left as an 
exercise to the reader.

\section{Problems}

\begin{enumerate}
\item[\textbf{1}]
\begin{enumerate}[label=\textbf{(\alph*)}]

\item We concluded an upper bound for the expected recursion depth $\mathbb E[H] \le \Theta(\log n)$ 
for \texttt{QuickSelect}. But to justify the expected complexity as $\Theta(\log n)$, 
show that $\mathbb E[H] \ge \Theta(\log n)$

\item Prove the Geometric Decline Theorem as stated in the text.

\end{enumerate}

\item[\textbf{2}]
Let $C_n$ be the number of comparisons made by \texttt{QuickSort} on an array of size \(n\). 
We already established the value of $\mathbb E[C_n]$ in the chapter itself.

\[
\mathbb E[C_n]=\sum\limits_{1 \le i < j \le n} \frac{2}{j-i+1}
\]

\begin{enumerate}[label=\textbf{(\alph*)}]
\item By grouping together all pairs with the same value of \(j-i\), show that
\[
\sum\limits_{1 \le i < j \le n} \frac{2}{j-i+1}
=
2\sum_{k=1}^{n-1}
\frac{n-k}{k+1}
\]

\item Let $H_n=\sum_{i=1}^{n}\frac1i$ be the \(n\)-th harmonic number. Using this and the 
above result show that
\[
\mathbb E[C_n]
=
2(n+1)H_n-4n = \Theta(n\log n)
\]
\end{enumerate}

\end{enumerate}

\chapter{The Classics}
\section{QuickSort}

In general, for an input array of size n -- to sort deterministically using only pairwise comparisons,
it can be proved via a decision tree that we need at least $n\log_2 n$ operations. From a 
time complexity point of view this is $\Theta(n\log n)$ time. \texttt{QuickSort} does not really improve upon that, but 
in practice it is very quick with a small constant factor. The STL 
library of \texttt{C++} uses \texttt{QuickSort} in its \texttt{std::sort()} function.\\

\subsection{A Simple Algorithm}

Consider the following pseudocode for \texttt{QuickSort}:
\begin{center}
\begin{minipage}{0.9\linewidth}
\begin{framed}
\begin{Verbatim}
QuickSort(A)
{
    choose an element p from A as the "pivot"
    partition A into A<p, A=p, A>p
    return {QuickSort(A<p) : (A=p) : QuickSort(A>p)}
}
\end{Verbatim}
\vspace{-4mm}
\end{framed}
\end{minipage}
\end{center}

\noindent Note that \texttt{A<p} is our notation for the elements of \texttt{A} that are strictly less than \texttt{p}.
Similarly for \texttt{A>p} and \texttt{A=p}.\\


\noindent A deterministic implementation may always choose the first or last element as pivot. 
Unfortunately, this can lead to very poor performance on adversarial inputs. 
For example, if the array is already sorted and we always choose the leftmost element as 
pivot, the recursion becomes extremely unbalanced:

\[
(n-1)+(n-2)+\dots+1
=
\Theta(n^2)
\]

\noindent Thus \texttt{QuickSort} has worst case complexity

\[
T(n)=\Theta(n^2)
\]

\noindent The standard randomised version instead chooses the pivot uniformly at random. This tiny 
modification dramatically changes the behaviour of the algorithm. 
Intuitively, it becomes very unlikely that we repeatedly choose extremely bad pivots.

\subsection{Expected Runtime}

\subsubsection*{Recurrence Relation}
Let \(T(n)\) denote the expected runtime of randomised \texttt{QuickSort} on 
an array of size \(n\) over all possible inputs.\\


\noindent Suppose the pivot finally ends up at position \(k\), where \(0\le k\le n-1\). Then the recursive subproblems have sizes \(k\) and \(n-1-k\). Since partitioning itself takes n operations, we obtain the recurrence

\[
T(n)
=
T(k)+T(n-1-k)+n
\]

\noindent Because the pivot is chosen uniformly at random, every value of \(k\) is equally likely. Taking expectation over all random choices made by the algorithm gives

\[
T(n)
=
n
+
\frac{1}{n}\sum_{k=0}^{n-1}
\Big(
T(k)+T(n-1-k)
\Big)
\]

\[
\implies
T(n)
=
n
+
\frac{2}{n}\sum_{k=0}^{n-1}T(k)
\quad
(\text{Using } \sum_{k=0}^{n-1}T(k)
=
\sum_{k=0}^{n-1}T(n-1-k))
\]

\noindent Changing the variable from $T(n)$ to $S(n)$ gives,

\[
\implies
S(n)-S(n-1)
=
cn+\frac{2}{n}S(n-1)
\quad (\text{Substituting } S(n)=\sum_{k=0}^{n}T(k))
\]
\[
\implies
S(n)
=
\left(1+\frac{2}{n}\right)S(n-1)+cn
\]

\[
\implies
\frac{S(n)}{(n+1)(n+2)}
=
\frac{S(n-1)}{n(n+1)}
+
\frac{cn}{(n+1)(n+2)}
\]

\[
\implies
\frac{S(n)}{(n+1)(n+2)}
-
\frac{S(n-1)}{n(n+1)}
=
\frac{cn}{(n+1)(n+2)}
\]

\vspace{0.3mm}
Summing this recurrence telescopically gives

\[
\frac{S(n)}{(n+1)(n+2)}
=
\Theta(\log n)
\]


\[
\implies
S(n)=\Theta(n^2\log n)
\]


\[
\implies
T(n)
=
S(n)-S(n-1)
=
\Theta(n\log n)
\]

Hence the expected runtime of randomised \texttt{QuickSort} is $
Theta(n\log n)$\\

\subsubsection*{Indicator Variables}

\noindent Here we explore an alternative method to arrive at the expected runtime of \texttt{QuickSort}. Observe 
that any pair of elements is compared at most once during the entire execution of \texttt{QuickSort}.

\noindent Consider the indicator variable,
\[
I_{ij}=
\begin{cases}
1,&\text{if elements }i,j\text{ are compared}\\
0,&\text{otherwise}
\end{cases}
\]

\noindent Then the total number of comparisons $C$ is given by

\[
C=\sum_{1\le i<j\le n}I_{ij}
\]

Two elements are compared only if one of them becomes the first pivot chosen 
among all elements lying between them in sorted order. Since all of them are equally likely, 
we have a 2 out of \(j-i+1\) chance of this happening.

\[
\Pr(I_{ij}=1)=\frac{2}{j-i+1}
\implies
\mathbb{E}[C]
=
\mathbb{E}[\sum_{1\le i<j\le n}I_{ij}]
=
\sum_{1\le i<j\le n}\frac{2}{j-i+1}
=
\Theta(n\log n)
\]

\section{QuickSelect}

\textbf{The Problem}: Find the \(k\)-th smallest element\footnote{This is commonly 
referred to as the \(k\)-th order statistic of the array.} of an unsorted input array.\\

\noindent An obvious method is to sort the array using \texttt{MergeSort}\footnote{\texttt{MergeSort} is a 
divide and conquer deterministic sort algorithm 
which runs in $\Theta(n\log n)$ time.} or \texttt{QuickSort} and then access the \(k\)-th element in $\Theta(1)$.
But since we only care about one element, it seems inefficient to sort the entire array. \\


\noindent\textbf{The Solution}:\\

\noindent We pick a pivot \(p\) and partition the array as before.
Basis the size of the partitions we can figure out which partition the \(k\)-th element is in.
If it is in the \texttt{A=p} partition, then we already have our answer!
Else we recurse into that partition and continue this process until we find the \(k\)-th element.

\begin{center}
\begin{minipage}{0.9\linewidth}
\begin{framed}
\begin{Verbatim}
QuickSelect(A,k)
{
    choose an element p from A as the "pivot"
    partition A into A<p, A=p, A>p
    if size(A<p) >= k
        return QuickSelect(A<p,k)
    else
    {
        if size(A<p)+size(A=p) >= k
            return p
        else
            return QuickSelect(A>p,k-size(A<p)-size(A=p))
    }
}
\end{Verbatim}
\vspace{-4mm}
\end{framed}
\end{minipage}
\end{center}

\noindent Intuitively, this is similar to \texttt{QuickSort}. However, unlike \texttt{QuickSort}, 
we recurse into only one side -- each step discarding a significant\footnote{On an expected basis.}
fraction of the array. This is a similar approach 
to Binary Search although not quite same since this does not assume a sorted array.

\subsection{Expected Runtime}

Let \(X_i\) denote the size of the search space after \(i\) recursive calls of 
\texttt{QuickSelect}. $(X_0=n)$\\

\noindent At each step, a pivot is chosen uniformly at random and the array is partitioned around it.
Depending on the rank we are searching for, \texttt{QuickSelect} recurses into exactly one of the two partitions. 
To obtain a worst-case bound, we imagine that the algorithm always recurses into the larger partition.\\


\noindent If the current search space has size \(x\), and the pivot ends up at position \(k\), 
then the larger partition has size $\max(k-1,x-k)$.\\

\noindent Averaging over all pivot positions,
\[
\mathbb E[X_{i+1}\mid X_i=x]
=
\frac1x
\sum_{k=1}^{x}
\max(k-1,x-k)
\le
\frac34(x-1)
\le
\frac34x
\]

\[
\implies
\mathbb E[X_{i+1}\mid X_i]
\le
\frac34 X_i
\]

Taking expectations and applying the law\footnote{See \autoref{total_expectation}.} of total expectation,

\[
\mathbb E[X_{i+1}]
=
\mathbb E\!\left[\mathbb E[X_{i+1}\mid X_i]\right]
\le
\frac34\mathbb E[X_i]
\]

\[
\implies \frac{\mathbb E[X_{i+1}]}{\mathbb E[X_i]} \le \frac34
\implies
\frac{\mathbb E[X_i]}{\mathbb E[X_0]}
\le
\left(\frac34\right)^i
\]
\[
\implies E[X_i] \le n (\frac{3}{4})^i \quad (\text{Using }\mathbb E[X_0]=X_0=n)
\]

\noindent Let $T$ be the random variable which denotes the number of recursive calls of \texttt{QuickSelect}. 
It is the first $i$ such that $X_i \le 1$. \\


\noindent Since the total runtime is proportional to the number of operations (taking 
constant of proportionality as 1 for simplicity) which 
are comparisons with the pivot in this case, we have 

\[
E[T_{run}] \le \sum_{i=1}^T n (\frac{3}{4})^i \le \sum_{i=1}^{\infty} n(\frac{3}{4})^i 
\]
\[
\implies E[T_{run}] \le n \cdot \frac{\frac{3}{4}}{1-\frac{3}{4}} = 3n
\]

So the expected runtime is \(\Theta(n)\)
\subsection{Expected Recursion Depth}

Recall that $T$ is the first $i$ such that $X_i \le 1$.
Since $X_i \le 1$ is equivalent to $i\ge T$, $i<T$ is equivalent to $X_i \ge 2$.
\[
\implies \Pr(i<T)
=
\Pr(X_i\ge2)
\le
\frac{\mathbb E[X_i]}{2}
\quad(\text{Using Markov's inequality})
\]

\noindent Upper bounding $\mathbb E[X_i]$,
\[
\Pr(X_i\ge2)
\le
\frac{\mathbb E[X_i]}{2}
\le
\frac n2\left(\frac34\right)^i
\]

\noindent Using the tail-expectation identity,
\[
\mathbb E[T]
=
\sum_{i=0}^{\infty}\Pr(T>i)
\]

\[
\implies
\mathbb E[T]
\le
\sum_{i=0}^{\infty}
\min\left(1,\frac n2\left(\frac34\right)^i\right) \quad (\text{Using the trivial } Pr(T>i) \le 1)
\]

\vspace{0.6em}
\noindent \textbf{The Splitting\footnote{I feel this is useful and common enough to warrant a name!} Technique}
We split the sum into two parts, and bound them or find 
them separately, thus finding our overall bound. Here we split according to when 
the min() changes from $1$ to $\frac n2\left(\frac34\right)^i$.\\
\[
\mathbb E[T] \le \sum_{i=0}^{m-1} 1 +
\sum_{i=m}^{\infty} \frac{n}{2} \left( \frac{3}{4} \right)^i
=m+ \sum_{i=m}^{\infty} \frac{n}{2} \left( \frac{3}{4} \right)^i
\]
\[
\quad \left(\text{where } m= \left\lceil \log_{\frac{4}{3}} \left( \frac{n}{2} \right) \right\rceil\right)
\]
\vspace{0.5em}
\noindent For the summation we can factor out the first term,

\[
\sum_{i=m}^{\infty} \frac{n}{2} \left( \frac{3}{4} \right)^i
=
\frac n2\left(\frac34\right)^m
\sum_{j=m}^{\infty}
\left(\frac34\right)^{j-m}
\]

\[
\begin{aligned}
\text{We have}\hspace{1em}
\frac n2\left(\frac34\right)^m \le 1
\text{ (By definition of }m)
&
\hspace{1em}\text{and }
&
\sum_{j=m}^{\infty}\left(\frac34\right)^{j-m}
=
\sum_{j=0}^{\infty}\left(\frac34\right)^{j}
=
\frac1{1-\frac34}
=
4
\end{aligned}
\]

\[
\implies
\sum_{i=m}^{\infty}
\frac n2\left(\frac34\right)^i
\le
4
\]

Combining the two bounds,

\[
\mathbb E[T]
\le
m+4
=
\left\lceil
\log_{4/3}\!\left(\frac n2\right)
\right\rceil
+4
\]

So we can conclude\footnote{Or can we? See Problems!} $\boxed{\mathbb E[T]=\Theta(\log n)}$


\section{Problems}

\begin{enumerate}
\item[\textbf{1}]
\begin{enumerate}[label=\textbf{(\alph*)}]
\item We concluded an upper bound for the recursion depth of \texttt{QuickSelect}. But to 
justify the complexity as $\Theta(\log n)$, show that the recursion depth is lower
bounded by $\Theta(\log n)$.
\item For a general series of random variables $X_0=n, X_1, X_2, \ldots$ and T being the first 
$i$ such that $X_i \le 1$, given $\frac{\mathbb E[X_{i+1}]}{\mathbb E[X_{i}]} \le p$ 
with $p<1$, show that $\mathbb E[T]$ is at most $\Theta(\log n)$
\end{enumerate}

\item[\textbf{2}]
Let $C_n$ be the number of comparisons made by \texttt{QuickSort} on an array of size \(n\). 

\begin{enumerate}[label=\textbf{(\alph*)}]

\item By grouping together all pairs with the same value of \(j-i\),
show that
\[
\mathbb E[C_n]=\sum\limits_{1 \le i < j \le n} \frac{2}{j-i+1}
\implies
\mathbb E[C_n]
=
2\sum_{k=1}^{n-1}
\frac{n-k}{k+1}
\]

\item Let $H_n=\sum_{i=1}^{n}\frac1i$ be the \(n\)-th harmonic number. Show that
\[
\mathbb E[C_n]
=
2(n+1)H_n-4n
\]
\end{enumerate}

\end{enumerate}
